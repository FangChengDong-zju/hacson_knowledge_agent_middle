## 2. 产品目标

这个 Agent 的核心目标：

1. 提高学生学习效率。
2. 提高教师备课效率。
3. 帮助教学管理者做课程整合，重点是课时压缩。

核心理念：

- 既然要精简，就必须抓住主干。
- 主干篇幅应该很小。
- 具体案例、长说明、操作细节、计算过程等不直接展开，只保留“一句话关键词 + 教材/章节/页码/原文片段索引”。
- 图片和图表不参与文本去重，应保留为 `visual_refs`，并能回到原文。

## 3. 赛题关键得分点

请优先围绕得分点推进，不要过度美化非核心内容：

- 能上传/调用多本教材。
- 能进行教材内容整合与凝练。
- 整合后目标篇幅约为原始内容的 30%。
- 每一项整合决策必须给出理由。
- 输出应可追溯来源。
- 需要有知识图谱。
- 需要能回答教师或学生问题。
- 需要能体现教师个性化需求对整合结果的影响。
- 页面要方便 AI 初筛和人工评审，条目、证据、JSON、报告要清晰可审计。

## 4. 当前架构与双入口

当前产品拆成两个入口：

### Case B：教师反馈整合与图谱生成

这是优先入口。

教师上传或调用教材，并输入备课要求、课程目标、压缩偏好。Agent 需要据此生成或修改：

- 整合决策 `integration_decisions`
- 30% 凝练版教材
- 决策图谱
- 审计记录

提示词优先级：

```text
教师写入要求 > Agent 默认整合策略
```

### Case A：基于已整合资料的信息查询

教师基于已整合资料或教材原文进行问答。

检索优先级：

1. 先查 Case B 已整合资料。
2. 再查 7 本教材原文 RAG chunk。
3. 如果仍不足，再进入 LLM/联网检索路径。

回答必须尽量带：

- 教材名
- 章节
- 页码
- 原文片段

## 8. Case B 当前能力边界

非常重要：此前 Case B 的整合决策、凝练教材和图谱大多是 demo 数据，不是完整 7 本 PDF 现场重新跑出来的。

后来已经补上“小批量真实 LLM 整合”入口：

- 系统从 `data/processed/textbooks.json` 里抽取真实教材片段。
- 组合：教师要求 + 默认策略 + JSON schema + 来源追溯硬约束 + 教材片段。
- 调用用户输入的 OpenAI-compatible API。
- 要求 LLM 返回合法 JSON。
- 返回后规范化为 `live_case_b_decisions`，并进入当前图谱/决策链路。

但是还没有做全量 7 本书的分批整合。

全量版本应是：

```text
章节分批
-> 候选簇发现
-> 批量 LLM 决策
-> 决策合并去重
-> 冲突复核
-> 最终 integrated_corpus / decision_graph / report 重生成
```
