# 中期自查整改记录

本文记录收到赛方中期自查报告后，在最后冲刺阶段完成的针对性整改。目标是提高可复现性、部署可用性、闭环证据和工程可信度。

## 1. 自查报告暴露的主要风险

根据中期自查截图，项目已具备基础闭环，但仍需重点补强以下方面：

1. 公网部署可访问，但云端无法访问本机 `E:/textbooks`，容易让评审误以为教材来源不可用。
2. 上传入口需要更明确地参与后续整合和 RAG，而不是只作为 UI 展示。
3. Agent 架构、闭环证据和评分点证据需要在仓库中更显眼。
4. README 需要承担评审首页作用，直接给出部署链接、演示路径和证据位置。
5. 代码工程方面需要尽量用小改动补可复现性，避免最后阶段大重构。

## 3. 上传解析能力说明

云端部署环境不能读取本机教材目录，因此新增上传解析链路：

```text
上传 TXT / MD / PDF / DOCX
-> extract_uploaded_text
-> build_uploaded_chunks
-> st.session_state.uploaded_textbook_chunks
-> get_available_textbook_chunks
-> Case B 整合片段选择 / Case A RAG 问答
```

解析策略：

- TXT / MD：按文本编码读取。
- PDF：使用 `pypdf` 解析前 80 页，适合云端演示；完整长教材建议本地解析。
- DOCX：使用 `python-docx` 读取段落。
- 上传生成的 chunk 会保留 `textbook`、`filename`、`chapter`、`source_label` 和文本片段。

| RAG 尚未接向量索引/rerank | 关键词检索能演示引用，但精度有限 | 后续接 BM25 + embedding + rerank |
| Docker 未补 | 部署进阶分受限 | 若时间允许补 Dockerfile / docker-compose |

## 5. 冲刺建议

若还剩少量时间，优先级如下：

1. 确认 Streamlit Cloud 部署自动更新成功。
2. 在云端上传一个小 TXT/MD 文件，验证上传解析后能显示 chunk 数。
3. 刷新 GitHub README，确认首页直接显示公网链接和评分点证据。
4. 若仍有时间，补一段 RAG Pipeline 说明或 Docker 部署说明。
