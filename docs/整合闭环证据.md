# 整合闭环证据

本文用于向评审说明：本项目不是只有静态 demo，而是已经形成“教材来源 -> 个性化需求 -> Agent 整合 -> 文档/图谱 -> 教师二次反馈 -> 问答”的闭环。每一步都对应可检查的页面位置、代码入口和证据文件。

## 1. 闭环总览

```text
1. 用户上传教材或指定本地路径
2. 用户填写个性化整合需求；不填则使用 Agent 默认模式
3. Agent 抽取教材片段，组合教师需求、默认策略和 JSON schema
4. Agent 生成 integration_decisions
5. 系统根据 decisions 生成整合文档 integrated_corpus
6. 系统根据 decisions 生成 decision_graph
7. 用户基于文档和图谱提出二次反馈
8. Feedback Agent 写入 decision_overrides
9. 文档、图谱和审计记录随反馈更新
10. 用户可切换到资料问答，优先基于当前整合资料回答
```

优先级：

```text
来源追溯硬约束 > 教师二次反馈 > 教师初始需求 > Agent 默认整理模式
```

## 2. 证据清单

| 闭环步骤 | 页面位置 | 代码/文件证据 | 可验证内容 |
|---|---|---|---|
| 教材来源 | Streamlit “1. 教材来源” | `streamlit_app.py::render_textbook_source_panel` | 支持本地路径和上传入口，显示已解析教材统计 |
| 默认整理策略 | Streamlit 左侧和整合 prompt | `streamlit_app.py::DEFAULT_INTEGRATION_POLICY` | 用户不输入需求时使用主干保留、细节降级、30% 压缩策略 |
| 用户个性化需求 | Streamlit “2. 整合需求与二次反馈” | `st.session_state.teacher_requirements` | 教师要求进入本轮 prompt，优先于默认策略 |
| 真实整合 prompt | “查看真实 LLM 整合输入/输出” | `build_case_b_live_integration_prompt` | prompt 包含教师要求、默认策略、source_items、JSON schema |
| LLM 返回解析 | 整合调用流程 | `strip_llm_json`, `normalize_case_b_live_payload` | LLM JSON 被规范化成 `live_case_b_decisions` |
| 整合决策 | “5. 整合依据：决策记录” | `data/demo/integration_decisions_demo.json` | 每条决策含 action、reason、sources、confidence |
| 整合文档 | “4. 整合结果：文档” | `data/demo/integrated_corpus_demo.json`, `report/整合报告.md` | 展示 30% 凝练版正文、来源、detail_index、visual_refs |
| 决策图谱 | “4. 整合结果：图谱” | `build_decision_graph_from_decisions`, `data/demo/decision_graph_demo.json` | 图谱节点和边来自整合决策，而非裸关键词 |
| 教师二次反馈 | 同一个聊天输入栏 | `handle_teacher_message`, `decision_overrides` | 支持保留、拆分、合并、降级、图表索引等反馈 |
| 反馈落地 | 文档和图谱刷新 | `apply_decision_overrides`, `build_decision_graph_from_decisions` | feedback 不只停留在聊天文本，会影响决策和图谱 |
| RAG 问答 | 左侧切换“资料问答” | `render_case_a_workspace`, `build_textbook_rag_answer` | 先查整合资料，再查教材原文 chunk，答案带来源 |
| 审计报告 | 报告折叠区 | `report/整合报告.md`, `data/demo/integration_audit_demo.json` | 评审可看到压缩比、决策摘要和教学完整性说明 |

## 3. 关键数据结构

### 3.1 integration_decisions

位置：

```text
data/demo/integration_decisions_demo.json
```

关键字段：

```json
{
  "decision_id": "decision_0001",
  "action": "merge | keep | remove | split | downgrade_detail | keep_visual_index",
  "reason_type": "共同主干 | 互补扩展 | 案例降级 | 图表归档 | 概念误合并",
  "target_concept": "string",
  "affected_sources": [
    {
      "textbook": "string",
      "chapter": "string",
      "page": 0,
      "source_text": "string"
    }
  ],
  "integrated_text": "string",
  "reason": "string",
  "confidence": 0.0
}
```

说明：

- 每条整合决策都能解释“为什么合并、保留、降级或拆分”。
- 每条决策都保留来源，避免生成不可追溯摘要。
- 图谱和文档都从该结构派生。

### 3.2 integrated_corpus

位置：

```text
data/demo/integrated_corpus_demo.json
```

用途：

- 输出用户真正可用的凝练版教材。
- 控制正文体量，目标不超过原始内容 30%。
- 把案例、长说明、操作步骤、图表等保留到 `detail_index` / `visual_refs`。

### 3.3 decision_graph

位置：

```text
data/demo/decision_graph_demo.json
```

用途：

- 把概念、整合动作、理由、来源教材和教师反馈串成图谱。
- 评审可以看到最终图谱来自“整合决策”，不是只做词频可视化。

## 4. 页面演示建议

评审演示时建议按以下顺序操作：

1. 打开公网部署：

   ```text
   https://hacson-knowledge-agent.streamlit.app
   ```

2. 在左侧选择：

   ```text
   教材整合：生成文档与图谱
   ```

3. 展示“1. 教材来源”：

   - 本地路径入口。
   - 上传教材入口。
   - 已解析教材统计。

4. 输入个性化需求：

   ```text
   面向临床见习学生，感染相关内容保留共同主干，病例细节降级为索引。
   ```

5. 点击“生成整合文档与图谱”：

   - 无 API Key 时展示待发送 prompt 和 source_items。
   - 有 API Key 时调用 OpenAI-compatible LLM 并生成 `live_case_b_decisions`。

6. 展开“4. 整合结果：文档”：

   - 查看凝练版教材。
   - 查看来源、detail_index 和 visual_refs。

7. 展开“4. 整合结果：图谱”：

   - 查看 decision graph。
   - 说明图谱来自整合决策。

8. 展开“5. 整合依据：决策记录”：

   - 查看每条 action、reason_type、reason、source。

9. 在输入栏继续反馈：

   ```text
   请把免疫应答保留在主干，不要降级。
   ```

10. 再次查看文档和图谱：

   - 反馈会写入 `decision_overrides`。
   - 文档中出现教师反馈调整。
   - 图谱出现教师反馈节点或高亮关系。

11. 切换到“资料问答”：

   - 询问某个教材知识点。
   - 系统先查整合资料，再查教材原文 chunk。

## 5. 为什么两本书不是最终产品边界

开发过程中曾使用《传染病学》和《医学微生物学》进行快速调试，这是为了节约 LLM 调用时间，不是产品主线。

正式流程面向用户指定的全部教材：

- 用户可上传多本教材。
- 本地演示读取 `E:/textbooks` 下的 7 本教材解析结果。
- `select_case_b_source_chunks` 默认不限制为两本书。
- 两本书队列只保留在“开发调试”折叠区。

## 6. 当前中期版本边界

- 公网部署无法访问本机 `E:/textbooks`，需要使用上传入口或查看 demo 数据。
- 真实 7 本教材全量 LLM 分批整合尚未完全生产化。
- 当前真实 LLM 链路支持主题批次整合、JSON 解析、规范化决策和图谱更新。
- Demo 数据用于保证无 API Key 时仍能展示整合文档、图谱和审计证据。

## 7. 结论

本项目已经形成可展示的教材整合闭环：

```text
教材输入可见
需求优先级可见
整合 prompt 可见
决策 JSON 可见
整合文档可见
决策图谱可见
教师反馈可落地
RAG 问答可追溯
报告证据可检查
```

这条闭环覆盖赛题 B1-B6 的主要功能点，也为 D 类 Agent 架构设计和 A 类文档可复现性提供了直接证据。
